# assistant: помощник для сотрудников по правилам владельца (49 € разово)

Сотрудник спрашивает в телефоне, помощник отвечает только из правил и прайса владельца и называет источник.
Чего нет в правилах, не придумывает: «спросите руководителя», а вопрос попадает в список для владельца.
Проверено поиском 27.11.2026, тесты без сети внизу.

## 1. Что получает клиент

| Ниша | Обещание на сайте | Что ставим |
|---|---|---|
| cleaning | «New cleaners ask a free helper on their phone about your rules, not you at 7am» / «Новенькие спрашивают твои правила у умной программы в телефоне, а не у тебя в 7 утра» | Бесплатно: NotebookLM в Google-аккаунте владельца, правила загружены файлом, доступ «Anyone with a link», ссылка уходит в WhatsApp. Сотрудник открывает её со своим Google-аккаунтом (на Android он почти у всех). Файл правил и инструкцию генерирует `gem/build-gem.mjs`. Пример правил: `kb/cleaning-blitz.json`. Gems больше не годятся: с 17.11.2026 они только для чтения, 17.12.2026 Google их удаляет. |
| office | «A helper on your team's phones answers their questions from your rules and prices» / «Программа-помощник в телефоне сотрудника отвечает на их вопросы по твоим правилам и ценам» | Страница-помощник `engine/` (Cloudflare Worker в аккаунте клиента, вход по коду команды). Отвечает с источником: «Preisliste 2026, p. 2: Payroll and bookkeeping». Проверка на 30 вопросах: `eval/office-steuer.json`. Альтернатива без кода: NotebookLM в Google Workspace офиса. |

## 2. Стек

- **Вариант «бесплатно» (cleaning):** NotebookLM. Отвечает только по загруженным источникам и показывает цитату. Публичная ссылка есть в бесплатном личном аккаунте, зрителю нужен любой Google-аккаунт. Минус бесплатного тарифа: зритель видит весь блокнот (источники тоже), режим «только чат» платный. Для правил уборки это не страшно.
- **Запасной вариант: Gemini Skill** (замена Gems с ноября 2026, бесплатно для личных аккаунтов 18+). Делиться можно только с веб-версии и по адресу почты каждого сотрудника, он ставит skill себе. Публичной ссылки для skills я не нашёл, поэтому «ссылка в WhatsApp» здесь не работает.
- **Вариант «страница команды» (office):** `engine/src/index.js` (Worker), `engine/public/index.html` (страница для телефона, без cookies, код команды в памяти телефона), модель `claude-haiku-5-5` через Anthropic Messages API, весь свод правил идёт в модель целиком с кэшированием (так вопрос по-русски находит правило на немецком). Лимит: около 120 000 знаков правил. Больше: NotebookLM.
- Ответы помощника проверяет код: нужен хотя бы один реальный раздел-источник, каждое число в ответе должно стоять в этом разделе. Иначе «спросите руководителя».

## 3. Подготовка один раз

1. Прогнать тесты, посмотреть `kb/*.json` (формат правил: раздел, источник, страница, текст). 20 мин.
2. Сделать себе тестовый блокнот NotebookLM по `kb/cleaning-blitz.json` (файл `rules-*.md` из `gem/build-gem.mjs`), открыть публичную ссылку со второго Google-аккаунта на телефоне, проверить вопросы из `eval/cleaning-blitz.json`. 30 мин.
3. Один раз задеплоить `engine/` в свой Cloudflare, прогнать `node eval/run-eval.mjs eval/office-steuer.json --live` со своим ключом (стоит центы). 1 ч.
4. Шаблон письма владельцу: «как прислать правила» (фото, голосовые, документы, лучше списком «если X, то Y»).

## 4. Шаги на заказ

### cleaning (NotebookLM, бесплатно): 1,5-2 ч
1. Разобрать присланное (фото, голосовые, списки) в `kb/<клиент>.json`: короткие разделы по темам. Модель помогает переписать, ты проверяешь. 40 мин.
2. `node gem/build-gem.mjs kb/<клиент>.json out/` даёт `instructions.txt` и `rules-<id>.md`. 2 мин.
3. На звонке в Google-аккаунте владельца: notebooklm.google.com, новый блокнот, загрузить `rules-<id>.md` как источник. Текст `instructions.txt` вставить в настройку чата блокнота (Configure chat, свой стиль), если она есть в аккаунте; если нет, он уже стоит первым разделом файла правил. 15 мин.
4. Проверка 10-12 вопросов из `eval/` плюс 2 вопроса «не из правил». 15 мин.
5. Share, «Anyone with a link». Владелец пересылает ссылку новеньким в WhatsApp, они открывают её со своим Google-аккаунтом. Сказать владельцу: не нажимать «отзыв» (feedback) на ответы, тогда содержимое не уходит людям Google на проверку. 5 мин.

### office (страница команды): 2,5-3 ч
1. Прайс и правила в `kb/<клиент>.json`, номера страниц прайса в поле `page`. 60 мин.
2. В Cloudflare клиента: `wrangler kv namespace create CHATS`, id в `wrangler.toml`, `KB_ID`, секреты `ANTHROPIC_API_KEY`, `TEAM_CODE`, `OWNER_CODE`; добавить импорт своего json в `engine/src/index.js`; `wrangler deploy`. 20 мин.
3. 30 вопросов: переписать `eval/office-steuer.json` под клиента (взять из присланных частых вопросов), запустить `--live`, исправить правила, пока не будет 28 из 30 и все «не из правил» честно не найдены. 45 мин.
4. Ссылку и код команды владельцу в WhatsApp. Показать владельцу `/unanswered?code=...`: вопросы, на которые нет правила. Раз в месяц он дополняет правила. 15 мин.

## 5. Что прислать клиенту

- [ ] Правила работы (любым видом: документ, фото, голосовые)
- [ ] Прайс (для office с номерами страниц, если есть PDF)
- [ ] Частые вопросы новеньких (10-30 штук), лучше их же словами
- [ ] На каких языках говорят сотрудники
- [ ] Кто «руководитель» в ответе «спросите ...»
- [ ] cleaning: Google-аккаунт владельца на звонке; у новеньких должен быть Google-аккаунт
- [ ] office: аккаунт Cloudflare, ключ Anthropic на офис (или Workspace для NotebookLM), AVV

## 7. Ограничения и право

- **Бесплатные сервисы Google (личный аккаунт).** NotebookLM по справке Google не обучает модели на источниках и вопросах; люди могут увидеть содержимое, только если нажать «отзыв» ([справка](https://support.google.com/notebooklm/answer/17004255)). Бесплатный Gemini (запасной путь со skill) при включённой «Keep Activity» использует чаты для улучшения моделей, часть читают люди ([Gemini Apps Privacy Hub](https://support.google.com/gemini/answer/13594961)). В обоих случаях AVV нет: никаких имён, адресов, кодов от ключей клиентов в вопросах и в правилах. Это стоит в инструкции и надо сказать владельцу.
- **Gems закрыты.** С 17.11.2026 Gems в личных аккаунтах только для чтения (ими нельзя пользоваться и нельзя создать новый), 17.12.2026 их удалят ([справка Google](https://support.google.com/gemini/answer/18560919)). Клиентам, которым раньше ставили Gem, перенести правила в NotebookLM. Если Google поменяет и NotebookLM, запасной путь: тот же `kb/*.json` в нашей странице команды (центы в месяц).
- **Офис с данными клиентов (Steuerberater и т.п.).** Помощник не для данных мандантов. Страница пишет «не вводите данные клиентов». Для Anthropic и Cloudflare действуют их DPA (ст. 28), нужен AVV между офисом и тобой. Для NotebookLM у офиса: только в Google Workspace (там данные не идут в обучение и есть AVV), не в личном аккаунте.
- **AI Act ст. 50:** страница помечена как автоматический помощник.
- **Не советник.** Инструкция запрещает налоговые, юридические и медицинские советы сверх правил. Вопрос про Grundfreibetrag в eval должен давать «нет в правилах».
- **Обновление правил:** владелец шлёт изменения тебе, ты правишь json и `wrangler deploy` (5 мин) или заменяешь источник в блокноте NotebookLM.

## Тесты

```
cd ops/kit/assistant/engine && node --test test/*.test.mjs
```
7 тестов без сети: ответ с источником и страницей, выдуманные числа и ответы без источника превращаются в «спросите руководителя»
и записываются в список, весь свод правил уходит в модель с кэшем (HTTP подменён), отказ при слишком большом своде,
прогон 30 вопросов с идеальной и с «ленивой» моделью (ленивая проваливается), код команды и список для владельца,
сборка файлов для NotebookLM (бывший Gem). Сборка Worker проверена через `wrangler deploy --dry-run`.
Живой прогон на реальной модели только вручную: `ANTHROPIC_API_KEY=... node eval/run-eval.mjs eval/office-steuer.json --live`.

## Файлы

- `kb/` правила (выдуманные примеры): клининг, офис
- `engine/` Worker и страница для телефона (использует `llm.js` и `store.js` из `../bot/engine/src/`)
- `gem/build-gem.mjs` инструкция и файл правил для NotebookLM (или Gemini Skill)
- `eval/` вопросы для проверки и запуск
