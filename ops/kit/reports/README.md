# reports: таблицы и учёт (19 € разово)

Набор, чтобы выполнить карточку `reports` во всех 6 нишах. Всё работает в Google-аккаунте клиента:
Google Таблица + Google Форма + Apps Script. Серверов, подписок и ключей ИИ здесь не нужно.
Факты проверены поиском 27.11.2026, ссылки в разделе 6. Тесты без сети: раздел «Тесты».

## Что лежит в папке

| Файл | Что это |
|---|---|
| `lib/ReportsCore.gs` | Вся логика: расход по остаткам, часы, наличные, долги по счетам, дозаказ, месяц по выписке, тексты на ru/uk/de/en. Один файл работает и в Apps Script, и в node. |
| `apps-script/Reports.gs` | Обвязка в таблице клиента: `setup()` создаёт форму, вкладки, триггеры; `refresh()`, `weekly()`, `importTill()`, `monthly()`. |
| `apps-script/appsscript.json` | Манифест (часовой пояс Berlin, нужные разрешения). |
| `examples/*.json` | Выдуманные клиенты: кафе, мастер, клининг, офис, магазин, «другое». Копируешь и меняешь под клиента. |
| `examples/bank.sample.csv` | Пример выписки банка (выдуманный). |
| `bin/config-gs.mjs` | Проверяет json клиента и делает `Config.gs` для вставки в Apps Script. |
| `bin/monthly.mjs` | Одна страница за месяц из CSV банка прямо у тебя на компьютере (для ниши «другое»). |
| `test/` | Тесты: node, без сети, с заглушками Google. |

Тип таблицы задаёт поле `kind` в json: `stock` (кафе), `reorder` (магазин), `hours` (мастера),
`cash` (клининг), `receivables` (офис), `monthly` (другое).

## 2. Стек

- **Google-аккаунт клиента** (Gmail, бесплатно): Таблица, Форма, Apps Script, Drive. Всё лежит у клиента, Михаил после сдачи доступ убирает.
- **Google Формы** для персонала: ссылка или QR, без входа в Google (сбор почты выключен, «один ответ на человека» выключен, загрузки файлов нет). `setup()` явно публикует форму и снимает «только для пользователей домена»: в новых версиях FormApp форма может создаваться неопубликованной, а в Google Workspace по умолчанию закрыта для чужих.
- **Apps Script** (бесплатно) с триггерами: ответ формы, правка, ежедневно, по понедельникам, по числам месяца.
- **Без ИИ**: считать деньги должна формула, а не модель. Ключей API нет.
- Касса (только магазин): то, что уже есть у клиента. Готово: CSV из Drive, CSV из письма, Zettle API. Другие кассы (SumUp, ready2order) добавляются как ещё один адаптер в `importTill()`, см. раздел 8.
- Ограничения бесплатного аккаунта Google: 100 получателей писем в день, 90 минут работы триггеров в день, 6 минут на один запуск. Нам нужно 1-2 письма в неделю и секунды работы.

## 3. Подготовка один раз (Михаил)

1. `cd ops/kit/reports && node --test test/*.test.mjs` (17 тестов, 1 секунда). 5 мин.
2. Завести тестовый Google-аккаунт (не личный), сделать в нём по одной таблице на каждый `kind` из `examples/`, пройти шаги «на заказ» ниже, заполнить форму с телефона, проверить письмо. 3-4 ч один раз.
3. Записать для себя 1-минутное видео «как открыть таблицу на телефоне и добавить на главный экран»: оно нужно каждому клиенту.
4. Взять шаблон договора обработки данных (AVV, ст. 28 GDPR) для случаев, когда видишь данные клиента (счета, выписки, имена персонала). Один раз, у юриста или из генератора.
5. Магазин: один раз выяснить, какие кассы у клиентов (Zettle, SumUp, ready2order, orderbird) и как каждая выгружает продажи. Записать в таблицу «касса -> адаптер -> колонки CSV».

## 4. Шаги на заказ

Общая схема (для всех ниш), 60-90 минут:

1. Бриф по телефону или WhatsApp: что считать (позиции, люди, объекты, категории). Заполнить json по примеру. 15-20 мин.
2. `node bin/config-gs.mjs client.json > Config.gs`. Ошибки конфига видны сразу. 2 мин.
3. Клиент сам создаёт пустую Google Таблицу и даёт тебе доступ «редактор» (или ты создаёшь у себя и переносишь владельца, но тогда триггеры придётся ставить заново клиенту). 5 мин.
4. В таблице: Расширения -> Apps Script. Создать 3 файла и вставить: `ReportsCore.gs`, `Reports.gs`, `Config.gs`; в настройках проекта показать `appsscript.json` и вставить его. 10 мин.
5. **`setup()` запускает клиент под своим аккаунтом** (созвон с демонстрацией экрана, с компьютера). Иначе форма, триггеры и письма будут жить на аккаунте Михаила. Google покажет «приложение не проверено»: Дополнительно -> Перейти, это нормально для своего скрипта. 10-15 мин.
6. Тест: открыть ссылку формы в браузере, где ты НЕ вошёл в Google (режим инкогнито), и заполнить 2-3 раза с телефона. `setup()` сам публикует форму и снимает «только для пользователей домена», но если у клиента Google Workspace, проверить вручную: Форма -> Настройки -> Ответы -> выключить «Только для пользователей домена». Потом открыть вкладку «Итоги», дождаться письма (или запустить `weekly()` вручную). 10 мин.
7. Ссылку на форму отправить персоналу (WhatsApp-группа), ссылку на таблицу владельцу. Показать, как открыть таблицу в приложении Google Таблицы. Убрать свой доступ редактора. 10 мин.

## 7. Ограничения, право, правила площадок

- **GDPR.** Данные лежат в Google-аккаунте клиента, клиент отвечает за них. Если Михаил при настройке видит имена, суммы, выписки, нужен AVV (договор обработки, ст. 28) между клиентом и Михаилом. После сдачи Михаил удаляет копии (фото счетов, CSV) и снимает свой доступ. Бесплатный Gmail для бизнес-данных юридически слабее Workspace: сказать клиенту, решает он.
- **Персонал.** Уборщицам и работникам сказать письменно, зачем форма и кто видит данные (короткий текст в описании формы). Геолокацию и фото не собираем.
- **Часы (trades, cleaning).** В строительстве и клининге по MiLoG § 17 начало, конец и продолжительность работы нужно записать не позже 7 дней; таблица это помечает. Таблица помогает вести учёт, но не заменяет расчёт зарплаты и не гарантирует прохождение проверки таможни (Zoll). Данные учёта хранить 2 года.
- **Наличные (cleaning).** Таблица показывает, кто сколько должен, это не Kassenbuch и не бухгалтерия. Для налоговой клиенту нужны свои чеки и учёт.
- **Счета и напоминания (office).** Напоминания отправляет сам владелец из своего WhatsApp или почты (ссылка wa.me только открывает чат с текстом), автоматической рассылки нет, поэтому правила WhatsApp Business API (шаблоны, окно 24 часа, оплата) не касаются. Третья ступень мягкая, юридических угроз и сборов за просрочку текст не содержит: проценты и Mahngebühr по § 288 BGB клиент добавляет сам, если хочет.
- **Месяц (other).** Это обзор «для тебя, не для налогов», не бухгалтерия и не налоговая консультация (StBerG). Если Михаил каждый месяц сам обрабатывает выписки, он обработчик данных, нужен AVV, и это регулярная работа (см. раздел 8).
- **Касса (shop).** Логин и пароль от кассы не берём: только выгрузку или API-ключ, который владелец создаёт сам и может отозвать. Касса с TSE остаётся главным учётом, таблица только подсказка для заказа.
- **Холодные письма, ИИ** здесь не используются.
