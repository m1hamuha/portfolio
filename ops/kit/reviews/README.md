# reviews: отзывы в Google

Цена на сайте: €15 разово, сторонних расходов у клиента нет.
Проверено 27.11.2026. Что не удалось проверить первоисточником, помечено «не проверено».

Главный вывод: разовая цена покрывает настройку и ответы на уже существующие отзывы. Тексты на сайте с 28.11.2026 обещают только это: ответы на все текущие отзывы, ссылку на отзыв для всех клиентов (без выборки довольных и без «5 звёзд»), у cafe ещё 30 дней скриншотов, у fitness одну просьбу только тем, кто согласился на сообщения, у clinic знак о новых отзывах. Всё, что раньше обещало ручную работу «каждый раз» (ответ на каждый новый отзыв, слежка в тот же день, публикация после каждого «ок»), с сайта убрано. Автомат на новые отзывы остаётся бонусом: скрипт сам находит новый отзыв, сам пишет черновик и сам шлёт его владельцу, Михаил после настройки в этом не участвует. Все обещания теперь «as-written», таблица в разделе 8.

Проверка скептиком (27.11.2026): автомат работает на аккаунте и ключах Михаила, значит это его постоянная обязанность и (сверх бесплатного лимита) его расход, пока клиент пользуется. Он не гарантирует черновик на каждый новый отзыв: через Places API видно только 5 отзывов (раздел 7). Поэтому на сайте «черновик на каждый новый» не обещан. Обещан только «знак о новых» у clinic: если Places показывает больше оценок, чем отдаёт текстов, владелец всё равно получает письмо «новая оценка, посмотри в Картах» (`owner_heads_up`, см. ниже).

Состав набора:

- `tool/review-kit.html` - страница без интернета: вводишь ссылку на отзыв или Place ID, получаешь QR, лист A4 для печати (4 карточки A6 и 8 наклеек), тексты просьбы на de, en, ru, uk и кнопку «Открыть в WhatsApp». Можно отдать и клиенту.
- `tool/build.mjs` - то же из `business.json` одной командой: `qr.svg`, `print.html`, `texts.md`.
- `replies/draft.mjs` - черновики ответов: из списка отзывов (JSON) или со скриншота (`--image`). ИИ: Anthropic, модель `claude-haiku-5-5`. Скриншоты работают только до даты `screenshots_until` в `business.json` (cafe: 30 дней с заказа, `untilFromStart(дата заказа)`); после неё скрипт отказывается и напоминает, что новые отзывы идут через автомат (`--force` для исключений).
- `ask/batch.mjs` - fitness: одна страница с кнопками WhatsApp, по кнопке на клиента, у кого есть согласие. Отправляет сам владелец со своего телефона.
- `watch/Watch.gs` - Apps Script на рабочем Google-аккаунте Михаила, один на всех клиентов: раз в 6 часов (свойство `WATCH_EVERY_HOURS`) проверяет отзывы, пишет черновик, шлёт письмо и Telegram, ссылку WhatsApp владельцу и (если есть доступ к API) ссылку «опубликовать». Если Places показывает новые оценки, но не отдаёт их текст, владелец (`owner_drafts` или `notify_owner`) получает письмо или Telegram «новая оценка, примерно N звёзд, посмотри в Картах» со ссылкой. Выключить на клиента: `"owner_heads_up": false`.
- `lib/Core.gs` - общие правила: тексты, проверка на запрещённые слова, промпт ответа, проверка ответа. Один и тот же файл работает в Apps Script, в node и в браузере.
- `examples/` - вымышленные клиенты: salon, cafe, clinic, trades, отзывы, список клиентов CSV.
- `test/` - офлайн-тесты: `node --test ops/kit/reviews/test/*.test.mjs` (21 тест, все проходят, сеть замокана).

## 1. Что получает клиент, по нишам

Общее для всех ниш (входит в €15):

- прямая ссылка на отзыв, QR, лист A4 с карточками и наклейками на языках клиента;
- текст просьбы об отзыве на нужных языках, один и тот же для всех клиентов (без скидок, без «если понравилось», без просьбы о 5 звёздах; `lintAsk` не пропускает такие слова);
- черновики ответов на все существующие отзывы без ответа (до 20 штук; больше по договорённости), публикует Михаил как менеджер или владелец сам;

## 2. Стек

- Ссылка на отзыв: из профиля (кнопка «Попросить оставить отзыв» / «Ask for reviews» даёт ссылку вида `g.page/r/.../review`) или собранная из Place ID: `https://search.google.com/local/writereview?placeid=...`. Place ID без доступа к профилю: страница Google «Place ID Finder» в документации Maps Platform.
- QR: своя копия библиотеки Kazuhiko Arase (MIT) в `vendor/`, всё офлайн, никаких сервисов коротких ссылок (они умирают, и QR на стойке перестаёт работать).
- Черновики: Anthropic Messages API, `claude-haiku-5-5` ($0.10 за 1 млн входных токенов, $0.50 за 1 млн выходных, данные skill claude-api от 03.11.2026). Один черновик около 1 500 токенов, это доли цента. Для злых и сложных отзывов `LLM_MODEL=claude-sonnet-5-5` ($2 / $10). Провайдер меняется в одном месте: `lib/llm.mjs` (node) и `LLM_PROVIDERS` в `Watch.gs`.
- Автомат: Google Apps Script на рабочем аккаунте Михаила (бесплатно), триггер раз в 6 часов по умолчанию (`WATCH_EVERY_HOURS`: 1, 2, 4, 6, 8 или 12). Два источника отзывов:
  - `places`: Places API (New), Place Details с полями `rating,userRatingCount,reviews`. Нужен только ключ API на проекте Google Cloud Михаила. Видно среднюю оценку, число оценок и максимум 5 отзывов, отсортированных по «релевантности», не по дате.
  - `gbp`: Business Profile API (старый v4, единственный, где есть отзывы и ответы). Видно все отзывы, можно публиковать ответ кнопкой. Нужен одобренный Google доступ (раздел 3) и права менеджера на профиле клиента.
- Уведомления: письмо (MailApp, бесплатно), Telegram-бот Михаила (бесплатно). Владельцу: письмо или Telegram (он один раз пишет боту /start). WhatsApp владельцу автоматически только через платный WhatsApp API, поэтому в WhatsApp пересылает Михаил одной кнопкой: в письме готовая ссылка `wa.me` с текстом.
- Встроенные уведомления Google: менеджер профиля может включить письма о новых отзывах (настройки уведомлений профиля). Это бесплатная страховка, включать всегда.

## 3. Один раз подготовить (Михаил)

1. Рабочий Google-аккаунт для клиентов (не личный). Им клиенты добавляют Михаила менеджером.
2. Google Cloud проект, включить Places API (New), создать ключ, ограничить ключ только этим API. Нужен платёжный аккаунт (карта), даже если укладываешься в бесплатный лимит. Поставить бюджетное оповещение на 1 €.
3. Apps Script: новый проект, файлы `lib/Core.gs` и `watch/Watch.gs`, манифест `watch/appsscript.json` (показать его: Настройки проекта > «Показывать appsscript.json»). Свойства скрипта: `OPERATOR_EMAIL`, `PLACES_API_KEY`, `ANTHROPIC_API_KEY`, `TG_BOT_TOKEN`, `TG_CHAT_ID`, `APPROVE_SECRET` (длинная случайная строка), `CLIENTS_JSON` = `[]`, по желанию `WATCH_EVERY_HOURS` (по умолчанию 6) и `DRAFT_KEEP_DAYS` (по умолчанию 14: неодобренные черновики потом удаляются, чтобы не переполнить хранилище свойств, 500 КБ на скрипт). Запустить `setupWatch` один раз, разрешить доступ.
4. Развернуть как веб-приложение (Развернуть > Новое развёртывание > Веб-приложение, «От моего имени», доступ «Все»), URL в `WEBAPP_URL`. Нужно только для кнопки «опубликовать». Ссылка из письма сначала только показывает текст и кнопку «Yes, post it»; публикует только нажатие кнопки (POST). Так сделано, потому что почтовые сканеры и превью ссылок сами открывают ссылки. Живьём на Apps Script этот шаг не проверен, проверить на первом клиенте.
5. Заявка на Business Profile API (по желанию, но без неё нет полной слежки и кнопки «опубликовать»). Требования по документации Google (страница prerequisites, видел через поиск, саму страницу открыть не удалось): профиль, проверенный и активный 60+ дней (свой или клиентский, которым управляешь), у фирмы есть сайт; Google Cloud проект; форма «Application for Basic API Access» на странице поддержки GBP API; почта заявителя должна быть владельцем или менеджером профиля. Ответ до 14 дней. Признак одобрения: квота 300 запросов в минуту вместо 0 в Cloud Console. Внимание: в августе 2026 разработчик на форуме Google писал, что после одобрения старый v4 (с отзывами) всё равно отдавал 403 SERVICE_DISABLED; ответа Google там нет, не проверено. Если API не дали, работаем через `places` и публикуем руками.
6. Telegram: бот у @BotFather, токен в свойства, свой chat id в `TG_CHAT_ID`.
7. Распечатать один `print.html` для себя и проверить QR камерой двух телефонов (iPhone и Android). Тесты проверяют структуру QR, но не реальное сканирование.
8. Шаблон договора обработки данных (AVV) для клиентов, у которых Михаил видит данные их клиентов (fitness: имена и телефоны). Взять типовой шаблон (например от Bitkom или GDD), не придумывать самому.

## 4. Шаги на заказ (реальное время)

Общее, 45-75 минут:

1. Бриф: ссылка на место в Картах, языки клиентов, «ты» или «вы», кто подписывает ответы, что можно предлагать при жалобе (`allowed_offers`, например «десерт за наш счёт»), есть ли сайт. 10 мин.
2. `business.json` по образцу из `examples/` (5 мин). Ссылка на отзыв: попросить клиента нажать «Попросить оставить отзыв» и прислать ссылку, или Place ID.
3. `node tool/build.mjs client.json --out out/<id>`: QR, лист печати, тексты. Открыть `print.html` в Chrome, печать A4, поля «нет», масштаб 100 %, сохранить PDF, отправить клиенту с текстами. 10 мин.
4. Старые отзывы без ответа: выписать в JSON (автор, звёзды, текст, «что было» от владельца) или скриншоты. `node replies/draft.mjs client.json reviews.json --out drafts.md`. Прочитать каждый черновик, поправить. Плохие отправить владельцу на «ок» ссылкой из файла. 15-30 мин на 20 отзывов.
5. Опубликовать: если Михаил менеджер, вставить сам (Google Карты > Ваш бизнес > Отзывы); иначе владелец вставляет, показать видео или скриншотами. 1-2 мин на отзыв.
6. Автомат: дописать клиента в `CLIENTS_JSON` (`source: "places"` или `"gbp"`, `owner_drafts: true`, почта владельца). Запустить `watchAll` вручную: первый запуск только запоминает существующие отзывы. 10 мин.

По нишам:

- cafe: при заказе вписать `"screenshots_until"` (дата заказа + 29 дней, `untilFromStart`). Скриншоты в эти 30 дней: `node replies/draft.mjs cafe.json --image shot.jpg --note "повар болел"`, 3-5 мин на отзыв. Отвечать в течение рабочего дня: на сайте показано «на следующий день» (afterLabel и подпись макета). После даты скрипт отказывается, новые отзывы идут через автомат (`owner_drafts: true`).
- fitness: CSV с клиентами из таблицы зала (имя, телефон, язык, согласие, дата визита). `node ask/batch.mjs gym.json clients.csv --out ask.html --sent sent.json --mark`, отправить `ask.html` владельцу, он открывает на телефоне и жмёт. 20 мин. Подписать AVV до получения списка.
- clinic: `health_guard: true`, `owner_drafts: true`, `notify_owner: true` уже в примере. Проверить каждый черновик на текущие отзывы глазами, 2 мин. Новые черновики и знаки о новых оценках уходят врачу сами.
- other: только ссылка на место: найти Place ID, `source: "places"`.
- trades, cleaning: показать, как переслать текст после работы (WhatsApp > Переслать или кнопка из `texts.md`). 5 мин.

## 5. Что клиент должен дать (чек-лист)

- [ ] Ссылку на место в Google Картах (или название и адрес)
- [ ] Для ответов от имени фирмы: добавить рабочий аккаунт Михаила менеджером профиля (без пароля). Для «вставляю сам» не нужно.
- [ ] Языки клиентов, обращение «ты» или «вы», подпись под ответами
- [ ] По плохим отзывам: что на самом деле было (одна строка)
- [ ] Что разрешено предлагать при жалобе (или ничего)
- [ ] Почта или Telegram, куда слать черновики новых отзывов
- [ ] fitness: список клиентов с отметкой согласия на сообщения в WhatsApp и подписанный AVV
- [ ] Номер WhatsApp владельца (для пересылки черновиков на «ок»)

Решение на будущее: автомат включён 3 месяца в цене, дальше маленькая подписка или выключить. Для клиентов на `gbp` Places не нужен.

## 7. Ограничения, право, правила площадок

- Правила Google ([Prohibited & restricted content](https://support.google.com/contributionpolicy/answer/7400114)): нельзя давать скидку, подарок, розыгрыш или деньги за отзыв, за изменение или удаление плохого отзыва. Просить честный отзыв можно. Выборочно просить отзыв только у довольных (review gating) прямо запрещено: в правилах Maps о fake engagement стоит «Discouraging or prohibiting negative reviews, or selectively soliciting positive reviews from customers» ([форма жалобы Google](https://support.google.com/maps/contact/14718793?hl=en), [Search Engine Land о добавлении этой строки](https://searchengineland.com/google-review-guidelines-say-discouraging-negative-or-selectively-soliciting-positive-reviews-is-not-allowed-388541)). Прежняя версия этого README говорила, что Google запрет убрал: это неверно, исправлено скептиком 27.11.2026. Поэтому: одинаковый текст всем, без «если понравилось», без «5 звёзд», без фильтра «сначала спросим, довольны ли». Это зашито в `lintAsk`, тексты с такими словами не собираются.
- Профиль могут ограничить, а отзывы удалить при повторных нарушениях «fake engagement». Покупка и обмен отзывами под запретом. В ЕС ещё и директива о защите потребителей и в Германии UWG: фальшивые отзывы и скрытая выборка недопустимы.
- Ответ на скидку после жалобы (десерт за наш счёт) разрешён только как извинение, не в обмен на изменение отзыва. Промпт это знает, `checkReply` ловит слова «удалить отзыв».
- UWG §7 и BGH VI ZR 225/17 (10.07.2018): просьба об отзыве по e-mail это реклама. Без согласия нельзя, исключение §7(3) только с правом отказа, указанным заранее. Для WhatsApp безопаснее только с согласием. Поэтому `ask/batch.mjs` берёт только строки с согласием. QR на стойке и устная просьба не требуют согласия. Холодные рассылки не делаем.
- GDPR: отзывы публичны, но в письмах и в запросе к ИИ это всё равно персональные данные. Anthropic: коммерческие условия API включают DPA (не проверено сегодня, проверить в консоли Anthropic перед первым заказом). Хранить: черновики только в почте и в свойствах скрипта, удаляются после публикации. Списки клиентов (fitness) только по AVV, после рассылки удалить CSV, хранить только `sent.json` (номера без имён), или пусть владелец держит его у себя.
- Клиника: ответ не должен подтверждать, что автор был пациентом, не упоминать лечение, дату, диагноз (врачебная тайна, §203 StGB и профессиональные правила). Пример «after» на сайте («в тот день был срочный пациент, запишем вас на первое время») подтверждает, что человек пациент: так писать нельзя. В `Core.gs` есть правило HEALTH RULE и проверка слов. В Telegram и в письме нет ничего, кроме публичного отзыва. Медицинские данные пациентов в набор не попадают.
- Условия Google Maps Platform: контент Places API нельзя кешировать и хранить, кроме Place ID ([policies Places API](https://developers.google.com/maps/documentation/places/web-service/policies)); при показе отзывов нужна атрибуция автора. Скрипт хранит только ID отзывов, среднюю оценку и число оценок (последние два формально тоже контент Places, держим только для сравнения с прошлым разом). Отправка текста отзыва в ИИ, чтобы написать ответ от имени самой фирмы: явного запрета в найденных текстах нет, но и разрешения нет, не проверено. Для клиентов, у которых Михаил менеджер, чистый путь это `gbp` (данные самой фирмы).
- Places API показывает максимум 5 отзывов по релевантности. Новый отзыв может не попасть в эти 5. Тогда автомат видит только, что оценок стало больше, и примерно какие (оценка по среднему, помечается «rough»), и шлёт ссылку на Карты. Для полной слежки нужен `gbp`.
- Публикация ответа менеджером: Google проверяет ответ и может попросить исправить. Ответ подписан именем фирмы, не именем Михаила. Автор отзыва получает уведомление.
- Число новых отзывов от Михаила не зависит: результат зависит от того, отправляет ли клиент ссылку. Поэтому цифры (8 новых, 31 отзыв, 15 со 100 уборок) с сайта убраны 28.11.2026.
